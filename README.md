## О проекте

Бот помогает не терять задачи: напоминания, списки по «компаниям» (это может быть семья, команда или личный список). Сейчас реализован каркас и профиль пользователя; доменная логика компаний и задач заложена в БД, UI для них — впереди.

**Архитектура (кратко):**

```
Telegram → Dispatcher → DBUserMiddleware → handlers → services → SQLAlchemy → PostgreSQL
```

| Папка | Назначение |
|-------|------------|
| `app/handlers/` | Роутеры aiogram (команды, callback, FSM) |
| `app/services/` | Бизнес-логика |
| `app/repositories/` | Запросы к БД (пока минимально) |
| `app/models/` | ORM-модели |
| `app/keyboards/` | Inline / reply-клавиатуры |
| `app/states/` | FSM-состояния |
| `app/middleware/` | Сессия и пользователь на каждый апдейт |
| `app/core/` | Настройки, engine, `TaskStatus` |
| `migrations/` | Alembic |

## Локальный запуск

### Требования

- Python 3.11+ (рекомендуется)
- Docker и Docker Compose (для Postgres)
- Токен бота от [@BotFather](https://t.me/BotFather)

### 1. Клонирование и окружение

```bash
git clone <url-репозитория> helper_tg_bot
cd helper_tg_bot

python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate

pip install -r requirements.txt
pip install aiogram
```

### 2. Переменные окружения

Создай файл `.env` в корне проекта:

```env
# PostgreSQL (для docker-compose)
POSTGRES_USER=helper
POSTGRES_PASSWORD=helper_secret
POSTGRES_DB=helper_db
POSTGRES_PORT=5432

# SQLAlchemy async URL
DATABASE_URL=postgresql+asyncpg://helper:helper_secret@localhost:5432/helper_db

# Telegram
BOT_TOKEN=123456:ABC-DEF...
```

`DATABASE_URL` должен использовать драйвер **asyncpg** (`postgresql+asyncpg://...`).

### 3. База данных

```bash
docker compose up -d
alembic upgrade head
```

Проверка, что контейнер поднят:

```bash
docker compose ps
```

### 4. Запуск бота

Из корня репозитория (чтобы импорты `app.*` работали):

```bash
python -m app.main
```

Остановка: `Ctrl+C`.

## Как протестировать у себя

1. Запусти Postgres и миграции (см. выше).
2. Запусти бота.
3. В Telegram открой своего бота → `/start`.
4. Проверь по чек-листу:

| Действие | Ожидание |
|----------|----------|
| `/start` | Приветствие + inline-меню |
| «Моя информация» | ID, имя, username, ссылка |
| «Обновить данные» → «Изменить имя» | FSM, ввод или «взять из профиля» |
| «Мои компании» | Пока без хендлера — кнопка может не отвечать |

После первого сообщения пользователь создаётся в таблице `users` (middleware).

Логи SQL при `echo=True` в `app/core/database.py` — для отладки; в проде позже выключить.

## Миграции

```bash
# применить все
alembic upgrade head

# откатить один шаг
alembic downgrade -1

# новая ревизия (после изменения models)
alembic revision --autogenerate -m "описание"
```

Текущая цепочка: `3a75b88465da` (users) → `b29a4bc938bc` (companies, tasks, …).

### 2026-06-11

**Версия:** Alpha 1.2.0

**Сделано:**
- ### 🗓 Обновления интерфейса и UX (Спринт: Полировка MVP)

#### 🎨 Визуальные улучшения и оптимизация UI
- * Стерильная очистка чата: Реализован бесшовный механизм удаления предыдущих инструкций бота и входящих сообщений пользователя при обновлении карточки задачи. Чат больше не забивается «столбиками» текста, сохраняя фокус на актуальном контенте.
- * Искусственные микро-паузы (UX Transitions): Добавлены асинхронные задержки (asyncio.sleep) между удалением контента пользователя и рендерингом новой карточки. Это позволило обойти резкие скачки интерфейса Telegram и добиться плавного, нативного визуального перехода.
- * Универсальные кликабельные сущности сотрудников:
  * Для пользователей с публичным @username реализована бесшовная интеграция ссылок через веб-протокол https://t.me/.
  * Для пользователей без юзернейма внедрен внутренний протокол tg://user?id=, позволяющий менеджеру переходить в профиль сотрудника в один клик прямо из текста карточки.

#### 🏗 Архитектурные изменения под капотом
- * Полный переход на HTML-разметку: Все шаблоны сообщений переведены с MarkdownV2 на ParseMode.HTML. Это обеспечило 100% стабильность системы и иммунитет к падениям бота из-за неэкранированных спецсимволов (., _, !, -) в именах пользователей или названиях задач.
- * Изоляция слоев (Refactoring): Начата глобальная очистка технического долга — логика форматирования текста вынесена из хэндлеров в изолированные сервисные функции-хелперы. Бизнес-слой больше не зависит от «грязных» объектов Telegram API (CallbackQuery/Message), что делает код готовым к покрытию автотестами.

### 2026-05-10

**Версия:** Alpha 1.1.0

**Сделано:**
- За последние два дня была проведена глубокая оптимизация архитектуры данных, внедрена система фоновых задач и расширен функционал распределения задач внутри компаний.
- ### ⚙️ 1. Асинхронные задачи и Инфраструктура (Celery)
- * **Интеграция Celery:** В проект заложена база для выноса «тяжелых» процессов в фоновый режим. Настроены воркеры Celery, которые позволят разгрузить основной поток бота при отправке уведомлений, интеграции с внешними CRM или обработке медиа.
- * **Изоляция модулей:** Создана отдельная структура для задач воркера (папка `workers/`), что позволяет масштабировать фоновые процессы независимо от самого Telegram-бота.

- ### 🏗 2. Рефакторинг и Слоёная Архитектура (Repository Pattern)
- * **Разделение зон ответственности:** Проект переведен на строгую слоёную структуру для исключения циклических импортов (`Circular Imports`):
  * `handlers/` — обработка входящих эвентов и интерфейс.
  * `services/` — бизнес-логика и оркестрация сценариев (например, модуль задач теперь может безопасно запрашивать данные из слоя сотрудников).
  * `repositories/` — чистый низкоуровневый CRUD (базовые кирпичики запросов к БД, работающие без бизнес-логики).
  * `utils/` — изолированные «слепые» инструменты общего назначения (форматирование, валидация), не зависящие от моделей БД.

- ### 📊 3. Оптимизация Базы Данных (SQLAlchemy 2.0 & PostgreSQL)
- * **Агрегационный запрос нагрузки:** Разработан сложный оптимизированный запрос для вывода списка сотрудников. За один проход базы данных с использованием составной группировки (`GROUP BY EmployeesCompany.id, User.id`):
  * Подтягиваются профили сотрудников из таблицы `Users`.
  * Динамически вычисляется количество строго *активных* задач на каждом пользователе через `func.count(Task.id)`.
  * Использован `.outerjoin()`, благодаря чему сотрудники с нулевой нагрузкой не выпадают из общей выборки.

- ### 📱 4. Пользовательский Интерфейс (UX/UI в Telegram)
- * **Карусель сотрудников:** Реализована динамическая пагинация (по 4 сотрудника на страницу) с отображением текущей страницы (`Страница X из Y`).
- * **Прозрачность для менеджмента:** В интерфейс назначения выводится детальная карточка со списком доступных людей и их текущей загрузкой, что позволяет эффективно распределять задачи в один клик.

- Сменить отправку новых сообщений на изменение(чтобы не захламлять чат)
